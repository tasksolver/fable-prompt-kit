# deep-interview — 딥 인터뷰

## 목적

막연한 요구를 인터뷰로 구체화한다. 작업 카테고리를 스스로 고려해 생각을 확장하고, 정해지지
않은 빈틈은 **최적의 선택지로 채워** 그대로 실행 가능한 프롬프트/스펙을 제안한다.

## 실행 모델·시점

- **실행 모델**: 아무 모델 — 이 스킬은 Fable 종속이 아니다. 큰 작업에 **착수하기 전**
  요구사항을 추출하는 단계이므로 어떤 세션에서든 유효하다.
- **시점·ROI**: 산출 스펙을 어떤 모델로 실행하든 쓸모 있지만, 긴 자율 턴(Fable류 장기
  실행)일수록 잘못된 가정의 비용이 커져 사전 인터뷰의 ROI가 특히 높다.

## 입력 처리

- `/deep-interview <막연한 요구 또는 초안>`
- 인자 없이 호출되면: "무엇을 만들고 싶은지 한 문장이라도 적어주세요"라고 요청하고 턴을
  끝낸다

## 절차

1. 입력에서 **작업 카테고리를 추정**하고, 카테고리별 필수 결정 항목 체크리스트를 확장한다:
   - 웹사이트/앱 → 대상 사용자 / 핵심 기능 / 스택 / 디자인 톤 / 콘텐츠 소스 / 배포
   - 에이전트 작업 → 목표·완료 기준 / 권한 경계 / 실행 시간 / 보고 형식
   - 문서/글 → 독자 / 목적 / 분량·형식 / 톤 / 원천 자료
   - 그 외 카테고리도 같은 요령으로 스스로 항목을 도출한다
2. **인터뷰 라운드** (최대 3라운드, 라운드당 질문 2–4개):
   - AskUserQuestion 도구가 있으면 선택지형으로 제시하고, 각 선택지에 장단점 한 줄을
     붙인다. 도구가 없으면 번호 목록 텍스트로 같은 형식을 유지한다
   - **모든 질문에서 권장안(Recommended)을 첫 번째 선택지로** 제시한다 — 사용자가 "다
     추천대로"라고 답하면 즉시 인터뷰를 종료하고 4단계로 간다. "2번은 X로, 나머지는
     추천대로" 같은 **부분 선택 + 부분 위임**도 동일하게 즉시 종료 처리한다
   - 이미 답이 나온 항목을 다시 묻지 않는다
3. 답을 얻지 못했거나 사용자가 위임한 빈틈은 **최적 기본값으로 채우고 그 근거를 기록**한다
   — 결정 요약표에서 "기본값(권장안 위임)"과 "기본값(미질문)"을 구분해 표기한다
4. 최종 산출 전 `${CLAUDE_PLUGIN_ROOT}/references/fable5-guidelines.md`를 참조해, 산출 프롬프트가
   목표·제약·성공 기준 구조를 갖추게 한다
5. 출력 후 "이 결과로 `/prompt-enhance`를 돌리면 표현 품질을 더 올릴 수 있다"고 안내한다

## 출력 형식

```
## 구체화된 프롬프트
(코드 블록 — 그대로 실행 가능한 형태)

## 결정 요약
| 항목 | 값 | 결정 주체(사용자/기본값) | 근거 |

## 다시 바꾸고 싶다면
- "N번 항목을 X로"라고 답하면 반영해 재생성합니다
```

## 엣지 케이스

- **이미 구체적인 요구**: 인터뷰를 생략하고 "충분히 구체적입니다"와 함께 바로 프롬프트를
  정리한다 (억지 질문 금지)
- **인터뷰 중 무응답/중단**: 현재까지의 답 + 기본값으로 결과를 생성한다 — 미완성 상태로
  대기하지 않는다
- 사용자 입력 언어를 따라 응답한다
