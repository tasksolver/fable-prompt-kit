# prompt-enhance — 프롬프트 강화

## 목적

사용자가 준 어떤 프롬프트든 Fable 5 공식 가이드라인에 맞춰 향상시킨다. 특히 이전 모델용
과잉 지시형(step-by-step) 프롬프트를 목표·제약·성공 기준 구조로 재작성한다.

## 실행 모델·시점

- **실행 모델**: 아무 모델. 이 스킬은 프롬프트를 Fable 세션에 **보내기 전**에 다듬는 준비
  작업이므로, 저렴한 Opus·Sonnet 세션에서 돌려도 된다.
- **대상 모델**: 강화된 프롬프트가 향하는 모델. 기본은 Fable 5로 가정한다. 사용자가 다른
  대상(Opus·Sonnet 등)을 언급하면 Fable 전용 규칙(§3.1 파라미터 제약, §1.4 de-prescribe)은
  적용하지 않고 범용 규칙(목표 지향·구조화·출력 형식)만 적용한다 — 절차 4 참조.

## 입력 처리

- `/prompt-enhance <프롬프트 원문>` — 원문을 그대로 강화 대상으로 삼는다
- 인자 없이 호출되면: "강화할 프롬프트를 붙여넣어 주세요"라고 요청하고 턴을 끝낸다
- 옵션 플래그 (프롬프트 원문 앞뒤 어디에 있어도 인식):
  - `--minimal`: 원문 구조를 최대 보존하고 최소 수정만 한다
  - `--target=<code|claude-ai|api>`: 해당 사용 서피스에 최적화 (code=Claude Code
    에이전틱 사용, claude-ai=대화형, api=시스템 프롬프트/자동화). 미지정 시 `code`를
    기본 가정으로 하되 서피스 특화 문구는 최소화한다
  - `--for=<fable|other>`: 강화 결과의 **대상 모델**. 미지정 시 `fable`(Fable 5) 가정.
    본문에서 대상 모델을 언급하면(예: "Sonnet에서 쓸 거야") 그 언급을 우선한다. `other`면
    절차 4의 대상 모델 분기가 발동한다

## 절차

1. `${CLAUDE_PLUGIN_ROOT}/references/fable5-guidelines.md`를 읽는다 (지침을
   기억에 의존하지 말 것 — 이 파일이 단일 원천이다)
2. 프롬프트의 **의도·카테고리를 파악**한다 (코딩/문서/에이전트 작업/창작…). 불명확해도
   추측으로 진행하되, 추측했다는 사실을 결과의 "변경 요약" 아래에 명시한다
3. **진단**: 가이드라인 기준 위반·누락 요소를 식별한다 — 모호한 지시, 목표 없는 단계
   나열, 과잉 스캐폴딩, 컨텍스트/제약 누락, 성공 기준 부재
4. **재작성 원칙**:
   - **대상 모델 분기**: 대상이 Fable 5면 전 규칙을 적용한다. 대상이 Opus·Sonnet 등 다른
     모델(`--for=other` 또는 본문 언급)이면 **범용 규칙만** 적용하고 Fable 전용 규칙은
     건너뛴다 — §3.1 샘플링/thinking 파라미터 제거·effort 조정, §1.4 de-prescribe(과잉
     지시 삭제)는 대상이 Fable일 때만. 목표 지향 구조·경계 명시·요청 이유·구조화·출력
     형식(§1.1~1.3, §2, §5)은 대상 모델과 무관하게 적용한다
   - 목표·제약·성공 기준이 드러나는 구조로 (Fable 5는 단계 나열보다 목표 지향 프롬프트에
     강하다)
   - **원문에 없는 요구사항을 지어내지 않는다** — 빈틈은 `[선택: ...]` 표기로 사용자에게
     위임하고 권장 기본값을 병기한다
   - 원문의 언어·톤을 유지한다 (한국어 입력 → 한국어 프롬프트)
5. 아래 출력 형식으로 응답한다

## 출력 형식

```
## 강화된 프롬프트
(코드 블록 — 바로 복사 가능한 완성형)

## 변경 요약
| 변경 | 근거 | 효과 |
(3–7행. 근거는 fable5-guidelines.md의 지침 이름 또는 이 스킬의 재작성 원칙.
표 바로 아래에 카테고리 추측 여부를 한 문장으로 명시)

## 남은 빈틈 (있을 때만)
- [선택: ...]로 표시한 항목과 권장 기본값
```

## 엣지 케이스

- **이미 훌륭한 프롬프트**: 억지 수정 금지. "수정 불필요" + 잘된 점 2가지를 짚고 끝낸다
- **프롬프트가 아닌 일반 질문**이 들어오면: "이 텍스트를 프롬프트로 강화할까요, 아니면
  질문에 답할까요?" 용도 확인 질문 1회 후 진행
- **안전 민감 주제** (보안·생명과학 인접 등 refusal 오탐 가능 영역): safety-refusal
  지침에 따라 의도 명시 문구(방어 목적·승인 맥락)를 추가 제안한다
