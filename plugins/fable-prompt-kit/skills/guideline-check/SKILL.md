# guideline-check — 가이드라인 준수 판별

## 목적

프롬프트가 Fable 5 가이드라인에 부합하는지 진단하고, 부족한 부분의 수정/제거 방법을
알려준다. prompt-enhance와 달리 **재작성하지 않고 진단 리포트만** 낸다 — 프롬프트의 최종
통제권은 사용자에게 남긴다.

## 실행 모델·시점

- **실행 모델**: 아무 모델. "Fable 5로 보낼 프롬프트"를 미리 점검하는 준비 작업이므로
  Opus·Sonnet 세션에서 돌려도 된다.
- **진단 전제**: 대상 모델은 기본 Fable 5. 사용자가 대상이 Opus·Sonnet이라고 밝히면
  thinking-effort 카테고리의 무효 파라미터·de-prescribe류 지적은 `해당 없음` 처리하고
  대상 무관한 범용 항목(clarity/structure/output-format)만 평가한다 — 절차 2 참조.

## 입력 처리

- `/guideline-check <프롬프트>` — 원문을 진단 대상으로 삼는다
- 인자 없이 호출되면: "진단할 프롬프트를 붙여넣어 주세요"라고 요청하고 턴을 끝낸다

## 절차

1. `${CLAUDE_PLUGIN_ROOT}/references/fable5-guidelines.md`를 읽는다
2. **6개 카테고리별 평가**: clarity / structure / thinking-effort / agentic /
   output-format / safety-refusal 각각에 대해 판정 `양호 / 개선 가능 / 미흡 / 해당
   없음` + 근거가 되는 프롬프트 구간 인용
   - 해당 카테고리와 무관한 프롬프트(예: 단발 질문에 agentic 항목)는 억지로 평가하지
     말고 `해당 없음` 처리
   - **대상 모델 분기**: 사용자가 대상 모델을 Fable 5가 아니라고 밝히면(예: "이건 Sonnet에
     보낼 거야") thinking-effort의 Fable 전용 지적(§3.1 무효 파라미터, §1.4 de-prescribe)은
     `해당 없음`으로 처리한다 — 그 파라미터·과잉 지시가 대상 모델에선 유효할 수 있기
     때문. 대상 미지정 시 Fable 5 전제로 평가한다
3. **발견 항목마다**: 문제 구간 인용 → 왜 문제인지(근거 지침) → **구체적 수정안 또는 제거
   권고** (바로 붙여넣을 수 있는 수정 예시 문구 포함)
4. **종합**: 카테고리 표 + 우선 수정 3가지
   - 판정-발견 매핑: 해당 카테고리에 발견 사항이 1건이라도 있으면 최소 `개선 가능`,
     refusal 유발·무효 지시급이면 `미흡`
   - 심각도 서열: refusal 유발 > 무효/모순 지시 > 품질 저하 > 스타일 개선
   - 엣지 케이스 "완벽에 가까운 프롬프트" 발동 조건: 발견 사항 0건

## 출력 형식

```
## 진단 결과
| 카테고리 | 판정 | 핵심 코멘트 |
(6행 고정 — 해당 없음 포함)

## 발견 사항 (심각도순)
### 1. <제목> — <카테고리>
> 인용: "..."
문제: ...
수정안: (예시 문구)

## 우선 수정 Top 3
```

## 엣지 케이스

- **완벽에 가까운 프롬프트**: 전 항목 양호 + "그대로 사용 가능" 명시. 억지 지적 금지 —
  발견 사항 섹션을 비우고 잘된 점을 1–2개 짚는다
- **매우 짧은 프롬프트 (<20자)**: 진단할 정보가 부족하다. 진단 대신 "정보가 부족해 딥
  인터뷰를 권장합니다 → `/deep-interview`"를 안내한다
- 사용자 입력 언어를 따라 응답한다 (한국어 입력 → 한국어 리포트)
