# fable-migrate — 이전 모델용 프롬프트·코드 이행 감사

## 목적

이전 모델(Opus·Sonnet 등)용으로 작성된 지시문·코드는 Fable 5에서 **품질을 떨어뜨리거나
(과잉 규정)**, **refusal을 유발하거나(추론 전사)**, **오류를 내거나(무효 파라미터)** 한다.
이 스킬은 프로젝트를 스캔해 그런 안티패턴을 찾아 심각도순 리포트와 수정안을 만든다.
공식 마이그레이션 가이드("Migrating to Claude Fable 5")의 권고를 코드베이스에 실제로
적용하는 도구다.

**전형적 사용 시점 3가지** — 공통 전제는 "이 프로젝트에 이전 모델 시절의 유산이 있다":

1. **전환 직전 점검**: 기존 프로젝트의 모델을 Fable 5로 바꾸기 전에 미리 돌려서, 바꾸는
   순간 터질 것(무효 파라미터 400 오류)과 조용히 나빠질 것(과잉 지시로 인한 품질 저하)을
   먼저 고친다
2. **전환 직후 문제 규명**: 모델만 바꿨더니 API가 400을 뱉거나, refusal이 나거나, 결과가
   이전만 못할 때 — 원인이 프로젝트에 남은 구모델용 지시·설정인지 확인한다
3. **물려받은 자산 감사**: 언제 작성됐는지 모를 CLAUDE.md·스킬·시스템 프롬프트를 그대로
   쓰고 있을 때, Fable 5 기준으로 유효한지 일괄 점검한다

형제 스킬과의 경계: **파일 스캔 없이 붙여넣은 프롬프트 하나**를 다룰 때는 진단이면
`/guideline-check`, 재작성이면 `/prompt-enhance`가 맞다. 이 스킬은 **프로젝트 자산
전체의 이행**이 대상이다. 유산이 없는 신규 프로젝트라면 이 스킬 대신 `/fable-snippets`가
맞다.

## 실행 모델·시점

- **실행 모델**: 아무 모델. 이행 감사 자체는 어떤 세션에서 돌려도 된다.
- **대상**: 이 스킬의 대상 시점은 **"Fable 5로의 이행" 그 자체**다 — 스캔·수정안은 프로젝트
  자산을 Fable 5 기준으로 맞추는 것을 전제로 한다.

## 입력 처리

- `/fable-migrate` — 현재 저장소 전체를 대상으로 스캔
- `/fable-migrate <경로>` — 특정 파일/디렉터리만. 경로가 존재하지 않으면 스캔 전에
  그 사실을 알리고 후보 경로를 제안한다
- `/fable-migrate --apply` — 진단 후 아래 표의 "자동 적용: 가능" 항목까지 적용.
  미지정 시 **리포트만** 내고 적용 여부를 묻는다

## 절차

1. `${CLAUDE_PLUGIN_ROOT}/references/fable5-guidelines.md`를 읽는다
2. **스캔 대상 수집** (존재하는 것만):
   - `CLAUDE.md`, `AGENTS.md`, `.claude/CLAUDE.md`, `**/.claude/skills/**/SKILL.md`,
     `.claude/agents/*.md`, `.claude/commands/*.md`
   - 코드 내 API 호출: 먼저 Anthropic 마커(`anthropic`, `claude-` 모델 ID,
     `messages.create`)로 파일을 좁힌 뒤, 그 파일들 안에서 시스템 프롬프트·파라미터를
     찾는다 (`grep -rl "system"` 같은 광범위 검색을 1차 필터로 쓰지 않는다 — 매치가
     너무 많다)
3. **안티패턴 진단** — 파일마다 아래 체크리스트를 적용. "자동 적용" 열이 `--apply`
   동작의 단일 기준이다:

   | # | 안티패턴 | 심각도 | 자동 적용 | 근거 |
   |---|---|---|---|---|
   | A1 | 추론 전사·에코 지시 ("생각 과정을 그대로 보여줘", reflection 패턴) | **높음 — refusal 유발** | 가능 | reasoning_extraction 분류기 (guidelines §6.2) |
   | A2 | 무효 API 파라미터: `thinking: disabled`/`budget_tokens`/`temperature`/`top_p`/`top_k`, assistant prefill | **높음 — 400 오류** | 가능 | Fable 5 API 제약 (§3.1) |
   | A3 | 짧은 클라이언트 타임아웃·블로킹 폴링 하네스 (120초 미만은 스킬 자체 권장 임계값 — §4.1은 "상향"만 명시) | 중간 — 정상 턴 절단 | 판단 필요 | 긴 턴 특성 (§4.1) |
   | A4 | step-by-step 실행 순서 강제, 세분화 체크리스트 | 중간 — 품질 저하 | 판단 필요 | 목표 지향 권고 (§1.1) |
   | A5 | 단순 검증 리마인더 ("반드시 테스트 돌려 확인") — 단, 검증 주기·방법을 설계한 지시(§4.8 패턴)는 권장 사항이므로 유지 | 낮음 — 불필요 | 가능 | 자기 검증 내장 (§1.4) |
   | A6 | 페르소나 과장·압박 ("세계 최고", "절대 실수 금지") | 낮음 — 무효 | 가능 | de-prescribe (§1.4) |
   | A7 | `max_tokens`가 thinking 합산을 고려하지 않음 (이전 모델 값 그대로) | 중간 | 판단 필요 | §3.1 |

4. **수정안 생성**: 발견 항목마다 원문 인용 → 왜 문제인지 → 대체 문구/코드 (guidelines의
   수정 패턴 사용). 삭제가 답이면 삭제를 권고 — 대체 문구를 억지로 만들지 않는다
5. **적용**:
   - 기본: 리포트 출력 후 "어떤 항목을 적용할까요?" 질문으로 턴 종료
   - `--apply`: 표의 "자동 적용: 가능" 항목(A1·A2·A5·A6)을 적용하고 diff 요약 제시.
     "판단 필요" 항목(A3·A4·A7)은 프로젝트 의도(응답 시간 요구, 승인 절차, 토큰 예산)
     판단이 필요하므로 제안만 한다. 자동 적용 대상이 0건이면 그 사실을 밝히고 리포트만
     낸다
   - 집계 규칙: 같은 파일의 같은 안티패턴은 위치별로 별도 항목, 단 하나의 API 호출 안의
     여러 무효 파라미터(A2)는 1건으로 합산. 한 문구가 두 패턴에 걸치면(예: 단계 목록 속
     검증 리마인더) 각각 별도 항목으로 보고한다
6. 프로젝트에 해당 파일이 하나도 없으면: 스캔 결과 "이행 대상 없음"과 함께 신규 프로젝트용
   권장 스니펫 안내(`/fable-snippets` 커맨드)로 마무리

## 출력 형식

```
## 이행 진단 리포트
| 파일 | 발견 | 최고 심각도 |
(스캔 요약 — 발견 0건 파일은 생략)

## 발견 사항 (심각도순)
### 1. <안티패턴 이름> — <파일:줄>
> 인용: "..."
문제 / 수정안 (코드 블록)
자동 적용: 가능 | 판단 필요

## 요약
- 높음 N건 (refusal·오류 위험) / 중간 N건 / 낮음 N건
- 다음 행동: --apply 재실행 또는 항목 번호 지정
```

## 엣지 케이스

- **깨끗한 프로젝트** (이미 Fable 5 기준으로 작성됨 포함): 억지 지적 금지 — "이행 준비
  완료" + 잘 되어 있는 점 1–2개
- **다른 프로바이더 코드**(OpenAI 등)가 섞여 있으면 해당 파일은 건너뛰고 그 사실만 표기
- **거대 저장소**(스캔 대상 30파일 초과): 우선순위(CLAUDE.md → skills → 코드)로 상위
  30개만 진단하고 나머지는 목록만 제시
- 사용자 입력 언어를 따라 응답한다
